Modifier-drag resize, ported from PowerToys

A user wrote in asking for the resize half of Windows 11's PowerToys Grab and Move. The Windows implementation is short and clean; the macOS port is mostly a different system call, with one real UX decision to make.

1 · The feature in one paragraph

PowerToys Grab and Move binds two gestures to a single modifier key (Alt by default, ⊞ Win optional). Modifier + left-drag moves the window — what AnyDrag already does. Modifier + right-drag resizes the window from the edge or corner closest to where the drag started, so the user never has to aim for a thin border. The two gestures share modifier-tracking, target-window resolution, throttling, and overlay code; the new logic for resize is small.

The Microsoft Learn docs page is consumer-facing. The implementation lives in one ~1 500-line C++ file: src/modules/GrabAndMove/GrabAndMove/main.cpp. Everything below is distilled from that file.

2 · The 8-anchor "nearest edge" pick

When the user presses modifier + right at point pt inside window rect rc, PowerToys picks which edge or corner is "grabbed" by enumerating eight anchor points — the four corners and the four edge midpoints — and selecting the one with the minimum squared distance to pt. That handle becomes g_currentHandle for the duration of the drag.

Figure 1. Eight candidates, one min-squared-distance comparison, no special cases. The same routine is called every mouse-move event during the drag — see §3.

The selection cost is trivial — eight squared-distance computations, then a min. PowerToys runs it inside the low-level mouse hook callback. Source: GetClosestHandle(), main.cpp:515.

3 · Live handle re-evaluation each frame

The non-obvious choice — and the thing that makes Grab and Move feel polished rather than sticky — is that PowerToys re-runs GetClosestHandle on every WM_MOUSEMOVE, not just at drag start. If the cursor crosses into a different "nearest" region mid-drag, the handle and cursor icon swap. So a user who starts dragging near the right edge but pulls diagonally up gets a clean transition from right-edge resize to top-right corner resize, with the cursor flipping from "↔" to "↗↙" at the boundary.

Subtle, but load-bearing

Without per-frame re-evaluation, the resize would feel "stuck" to whichever edge the drag started nearest. The user notices it instantly when comparing the two implementations side-by-side — even if they can't name what's different.

Figure 2. Per-frame GetClosestHandle + cursor swap. The window rect itself reshapes between the two snapshots — re-evaluation uses the current rect, not the original.

4 · Delta math, per handle

Once the handle is known, applying the mouse-move delta is a single switch. PowerToys' version:

int dx = pt.x - g_resizeLast.x;
int dy = pt.y - g_resizeLast.y;
RECT nr = g_resizeWndRect;

switch (g_currentHandle) {
case TOP_LEFT:     nr.left  += dx; nr.top    += dy; break;
case TOP:          nr.top   += dy;                  break;
case TOP_RIGHT:    nr.right += dx; nr.top    += dy; break;
case RIGHT:        nr.right += dx;                  break;
case BOTTOM_RIGHT: nr.right += dx; nr.bottom += dy; break;
case BOTTOM:       nr.bottom += dy;                 break;
case BOTTOM_LEFT:  nr.left  += dx; nr.bottom += dy; break;
case LEFT:         nr.left  += dx;                  break;
}

// Enforce MIN_WINDOW_WIDTH=150, MIN_WINDOW_HEIGHT=50.
// If the "moving" edge would cross past the opposite edge, clamp.

The minimum-size enforcement at the bottom matters: if the user drags the left edge to the right past nr.right − 150, PowerToys snaps nr.left so the rect stays 150 px wide rather than letting it invert or collapse. Same for height with 50 px. Source: main.cpp:1252–1279.

Figure 3. Orange edges grow/shrink with the cursor; black edges stay anchored. The center cell is illustrative — that's where modifier+left-drag (move) lives in AnyDrag.

5 · Frame budget: throttle + async repaint

Mouse events arrive faster than any window server wants to repaint. PowerToys gates the per-frame work with QueryPerformanceCounter:

static constexpr ULONGLONG THROTTLE_INTERVAL_MS = 16;  // ~60 Hz

if (now - g_lastMoveTick >= THROTTLE_INTERVAL_MS) {
    g_lastMoveTick = now;
    HandleDragResize(ms->pt);
}

And the actual move call uses async repaint so the hook callback doesn't block on the target app's paint loop:

SetWindowPos(target, nullptr,
             nr.left, nr.top, w, h,
             SWP_NOZORDER | SWP_NOACTIVATE | SWP_ASYNCWINDOWPOS);

The SWP_ASYNCWINDOWPOS flag matters because the resize calls into a different process — without it, a slow target app would stall the hook thread for everyone. The macOS equivalent (see §6) is also asynchronous in its own way.

6 · Mapping Windows primitives to macOS

Most of the design transfers cleanly. The one fundamental difference: PowerToys' move path uses SetWindowPos, which writes window geometry directly into the window manager. AnyDrag's move path bypasses even that by rewriting cursor coordinates into the title-bar zone and letting the window server do a native drag — a trick that has no analogue for resize. Resize must go through the Accessibility API per frame.

Cost summary

One genuinely new slow path (the per-frame AX call), one minor cursor-asset quirk, and one resizability probe that's best-effort. Everything else is either trivially portable or already implemented in AnyDrag's DragEngine.

7 · The gesture conflict

AnyDrag already binds all three mouse buttons with the modifier:

ButtonCurrent behavior (modifier held)Source
Left Move window (title-bar redirect) DragEngine.handleEvent · .leftMouseDown
Right Open the tile overlay (halves / quarters / fill) DragEngine.handleEvent · .rightMouseDown · TilingPanel
Middle Configurable: off / drag / tile-by-direction MiddleAction enum

The slot PowerToys uses for resize — modifier + right-drag — is the slot AnyDrag uses for the tile overlay. Both are unambiguously "the right-button drag with modifier held," so something has to give.

MiddleAction enum ⌃ + middle-drag → resize (new mode) ⌃ + right-drag → tile overlay (unchanged) + clean separation · − needs middle button C · Right-button mode toggle settings radio: tile or resize, not both ⌃ + right-drag → tile or resize (user picks one in Settings) + matches PowerToys verbatim · − loses tile-by-default D · Drag-direction discriminates first ~6 px of right-drag picks the mode ⌃ + right-drag >0 dist → resize from nearest edge ⌃ + right-click (tap) → tile overlay + both keep right-button · − two latencies to tune
Figure 4. Trade-offs marked at the bottom of each card. Option D ringed in orange is the recommendation — see commentary below.

Why D is the recommendation

Tile overlay already commits on a click (mouse-down → menu shows → click a zone → mouse-up). It barely uses the drag dimension. Resize fundamentally is a drag. So the gesture grammar already separates them: a tap-then-pick versus a press-and-drag. We can keep both on right-button with a small distance threshold (the same tileDirectionThreshold = 30 px AnyDrag already uses for middle-button tile-by-direction) as the discriminator. If the user releases without crossing the threshold, the tile overlay opens; if they cross it, the engine commits to a resize gesture and the overlay never shows. No settings UI change, no key gymnastics, no regression.

Risk to verify

Tile overlay opens on mouse-down today — it doesn't wait for movement. Switching to a "show overlay only after threshold not crossed" model would delay overlay appearance by the threshold-cross window, which feels sluggish if too long. Prototype the threshold (try 6–10 px) and ship the smallest value that doesn't false-positive on hand jitter.

8 · Implementation skeleton

Putting the pieces together, the new code lives almost entirely inside DragEngine.handleEvent alongside the existing left/right/middle branches. Pseudo-Swift, eliding the locking and overlay plumbing:

enum ResizeHandle { case topLeft, top, topRight, right, bottomRight, bottom, bottomLeft, left }

struct ResizeGesture {
    let target: AXUIElement
    let startRect: CGRect
    let startPoint: CGPoint
    var currentRect: CGRect
    var currentHandle: ResizeHandle
    var lastUpdateAt: CFTimeInterval
}

static func closestHandle(point: CGPoint, in rect: CGRect) -> ResizeHandle {
    let midX = rect.midX, midY = rect.midY
    let anchors: [(CGPoint, ResizeHandle)] = [
        (CGPoint(x: rect.minX, y: rect.minY), .topLeft),
        (CGPoint(x: midX,      y: rect.minY), .top),
        (CGPoint(x: rect.maxX, y: rect.minY), .topRight),
        (CGPoint(x: rect.maxX, y: midY),      .right),
        (CGPoint(x: rect.maxX, y: rect.maxY), .bottomRight),
        (CGPoint(x: midX,      y: rect.maxY), .bottom),
        (CGPoint(x: rect.minX, y: rect.maxY), .bottomLeft),
        (CGPoint(x: rect.minX, y: midY),      .left),
    ]
    return anchors.min(by: { a, b in
        a.0.squaredDistance(to: point) < b.0.squaredDistance(to: point)
    })!.1
}

// Inside handleEvent, per mouse-move during an active resize:
let now = CACurrentMediaTime()
guard now - gesture.lastUpdateAt >= 0.016 else { return }
gesture.lastUpdateAt = now

gesture.currentHandle = closestHandle(point: cursor, in: gesture.currentRect)
setCursorForHandle(gesture.currentHandle)

var r = gesture.currentRect
let d = cursor - lastCursor
switch gesture.currentHandle {
case .topLeft:     r.origin.x += d.x; r.origin.y += d.y; r.size.width -= d.x; r.size.height -= d.y
case .top:         r.origin.y += d.y;                    r.size.height -= d.y
case .topRight:                       r.origin.y += d.y; r.size.width += d.x; r.size.height -= d.y
case .right:                                              r.size.width += d.x
case .bottomRight:                                        r.size.width += d.x; r.size.height += d.y
case .bottom:                                                                  r.size.height += d.y
case .bottomLeft:  r.origin.x += d.x;                    r.size.width -= d.x; r.size.height += d.y
case .left:        r.origin.x += d.x;                    r.size.width -= d.x
}
r = clampToMinimum(r, width: 150, height: 50)
gesture.currentRect = r

// One AX call for size, one for position if a top/left edge moved.
AXUIElementSetAttributeValue(gesture.target, kAXSizeAttribute, r.size.asAXValue())
if handleMovesOrigin { AXUIElementSetAttributeValue(gesture.target, kAXPositionAttribute, r.origin.asAXValue()) }

9 · What would break if you removed each piece

Remove…SymptomSeverity
closestHandle per-frame re-evaluation Drag feels "stuck" to the starting edge. Crossing the rect diagonally produces a slow corner-drag that should have switched to a fast edge-drag. MEDIUM
16 ms throttle Every mouse event becomes a 5–10 ms AX IPC call. CPU spike during active drag, frame drops on the target app, possible UI hangs. HIGH
Minimum-size clamp (150 × 50) User can collapse a window to zero or invert it. AppKit recovers in most cases but some apps render garbage at width = 0. MEDIUM
kAXResizableAttribute probe Resize attempt on a fixed-size dialog (e.g. About windows, alerts). AX call silently fails or partially succeeds — confusing. MEDIUM
Cursor swap per handle User has no visual feedback for which edge is being grabbed. Less polish, fully usable. LOW
Overlay + geometry readout No live X/Y/W/H display during drag. Power users miss it; most users won't notice. LOW
Drag-distance threshold for the tile-vs-resize discriminator (Option D) Resize gesture and tile-overlay gesture become ambiguous on right-button — user gets one when expecting the other. Blocks shipping. HIGH

10 · Decisions needed before coding

  1. Gesture binding. §7 recommends Option D (drag-distance discriminator), but A/B/C are all viable. Final call belongs to whoever owns the AnyDrag UX.
  2. Cursor fidelity. Use private SPI NSCursor(named: "resizenorthwestsoutheast") for diagonal cursors (Finder does), or ship with only ↔ and ↕ and accept a small regression for corner drags?
  3. Overlay + geometry readout in v1, or v1.1? Implementation is small but adds a settings toggle and translation strings. Reasonable to defer.
  4. Per-app excluded-from-resize list. PowerToys ships it; AnyDrag could reuse the existing Preferences store. Probably v1.1.
  5. Should resize be a feature toggle in Advanced settings (like the existing maximizeEnabled, tilingEnabled toggles)? Default on or off?
